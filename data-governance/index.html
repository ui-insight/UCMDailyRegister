    Data governance and privacy¶

    Reviewed against repository code on October 22, 2026. This describes the implemented application; it does not attest to live production configuration or institutional approval. Accountable people and approval references are tracked in Governance decisions.

    Data inventory and classification¶

    The data dictionary inventories every ORM table and column. Its machine-readable source also drives the staff governance page. Classification is provisional until the Data Owner and institutional reviewers approve the mapping to APM 30.11; local labels are not institutional approval.

    Local handling label Working definition Examples
    Public Reviewed content approved for public release, or public reference data Published issue copy, public calendar feed, category labels
    Internal Working or operational data available to authorized roles Unpublished copy, SLC-only event details, ops verdicts, AI provenance
    Confidential Contact information, free text with incidental personal information, or credentials Submitter/contact email, notes, feedback details, identity claims, session tokens
    Restricted Placeholder for information requiring additional institutional controls No intentional collection; unexpected sensitive content needs incident review

    Unpublished content is not classified Public solely because it may later be published. Treat mixed datasets and generated output according to the most sensitive content present. Free-text fields, links, JSON flags, and images can contain information beyond their intended purpose.

    There is no user table. This does not mean identity data is absent or that nothing is persisted: the browser stores the app JWT, including identifiable claims. JWT expiry ends authorization; it does not remotely erase localStorage on an inactive browser. Signed cookies and JWTs are not encrypted storage.

    The app does not intentionally request student IDs, education records, health or financial records, passwords, or government identifiers. Free text and uploads can still contain them. FERPA scope and directory-information treatment require institutional privacy review; no categorical legal conclusion is asserted here. If unexpected protected content is found, stop further sharing and follow the incident procedure below.

    Authentication and authorization¶

    AUTH_PROVIDER=oidc uses Entra's confidential-client authorization-code flow. The backend verifies the response, maps App Roles (or Graph groups), and issues an HS256 app JWT. Only bearer credentials count in this mode. Unmapped users are refused; role changes take effect at next sign-in or token expiry. Browser sign-out clears local state and goes through Entra logout. There is no per-token revocation service.

    AUTH_PROVIDER=header accepts X-Trusted-User-Role only with the configured X-Trusted-Auth-Secret. Bearer tokens do not grant access in this mode. X-User-Role is rejected. The frontend proxy overwrites trusted headers. If the proxy asserts staff for every request, everyone who can reach it receives staff access. This is a prototype boundary, not evidence of individual sign-in. Production should use OIDC; verify actual enablement separately for each host. See Deployment and ADR-001.

    All paths below are under /api/v1. Public means no identity credential is required; it does not imply that every column in a response is approved for publication.

    SLC redaction removes dedicated contact fields, not names/emails embedded in event copy or links. Staff inherit both triage capabilities; SLC and ops are separate roles. Current settings/sections/schedule read endpoints are public; they must contain no secrets. API responses, permission tests, and the API reference are the implementation evidence.

    Data flows and external processing¶

    1. A public or authorized caller submits copy, contact fields, notes, links and dates through React → nginx → FastAPI → database. Staff can upload an image.
    2. Staff trigger newsletter editing. Active DB style rules form the system prompt. The user prompt contains headline/body, category, submitter notes, provided links including URLs/parameters, and editor instructions. A compliance repair request can resend the original input, generated draft and deterministic findings. Dedicated submitter name/email, assignment, and editorial notes columns are not explicitly inserted, but personal data in content is not automatically sanitized. Returned copy, flags, change summaries, model/provider and editor instructions may persist in edit history.
    3. Trumba calendar pages/feed and PeopleAdmin postings are fetched on demand. SLC harvesting upserts structured JSON-feed occurrences in harvested_events. SLC flagging promotes an event into a submission and records its provenance.
    4. A harvest queues ops classification in the background. A separate MindRouter provider receives title, description (up to 4,000 characters), location and category. It uses OPS_CLASSIFIER_*, with endpoint/key falling back to MINDROUTER_*; it is independent of LLM_PROVIDER. Needs/confidence/rationale and staff verdicts persist. Rationale may quote source text. Staff judgments survive reassessment; assessment content hashes identify source versions.
    5. Approved submissions and external/recurring items become issue snapshots. Staff download Word exports. Dedicated contact columns and internal metadata are not automatically exported, but contact text intentionally in copy remains.
    6. Feedback stores submitted free text and lightweight browser context. Its notifier is disabled. Staff may prepare GitHub Markdown containing report details and context; review/redact before opening or publishing a GitHub issue, including the URL prefill sent to GitHub. No automatic external delivery is enabled. Future notifier payloads can contain summary and optional contact email and require destination approval.
    Processor Configured use Evidence required before an institutional assurance
    Anthropic / OpenAI Selected newsletter editor; local default is Claude Approved processor/model, endpoint and account configuration, contract retention/training/residency terms, external sharing authorization
    MindRouter Optional newsletter editor; dedicated ops classifier Approved endpoint/model and operating controls; configurable URLs alone do not prove campus-only routing
    Microsoft Entra / Graph Sign-in and optional group lookup Registration/consent, scopes, role assignments, secret ownership and rotation
    Trumba / PeopleAdmin Public source reads Source purpose, endpoint inventory and operational limits

    No external-provider residency or zero-retention claim follows from source code. No-training terms, where agreed, do not imply zero retention. Processor approval references remain pending in the decision register. See AI editing.

    Uploads and minimization¶

    JPEG, PNG, GIF and WebP uploads are UUID-named in the upload volume. Supported still images are decoded and rewritten without metadata; processing failure rejects the upload. GIF does not receive the same EXIF rewrite. Image content can itself identify people. Deleting a submission through the existing endpoint does not currently guarantee upload-file disposal; use the reviewed disposal design rather than claiming endpoint deletion meets retention policy.

    Do not put protected records or credentials in content, links, notes or feedback. Review free text before AI processing/publication/export. Automated PII detection and source-wide sanitization are not implemented and would not guarantee removal.

    Retention, logging and ownership¶

    Retention and disposal distinguishes proposed periods from enforced behavior, documents source/archive dependencies, and provides a read-only inventory command. No automatic purge is enabled. The Data Owner must resolve periods, holds and academic-year boundaries before destructive scheduling.

    Audit logging specifies minimized diagnostics, Docker limits, remaining access-audit work, and unverified aggregation/retention targets. Backup and recovery describes versioned backup and release-specific recovery procedures; job installation and restore proof remain operational evidence to collect.

    The decision register records accountable-role vacancies, classification, processor, dev/test, tooling and approval decisions. Never treat a blank approval reference as approval. Schema changes must update ORM, migrations, API/types, catalog, vocabulary baseline and docs in the same review; run the repository governance check before merging.

    Incident handling¶

    If protected or unexpectedly sensitive content is exposed or submitted, pause further AI/export/publication, restrict access, preserve minimized evidence and notify the University Information Security Office through the established campus process. Coordinate with the technical owner and UCM; do not copy the content into GitHub, chat or email during investigation. Determine scope, containment and any notification obligation with authorized institutional responders. Use the recovery runbook for service restoration and record a post-incident review.
